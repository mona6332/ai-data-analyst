# AI 데이터 분석 에이전트 — 서비스 흐름과 인프라

## 1. 사용자 관점 흐름
```
대시보드·자동 리포트에서 특이사항 발견
        │ (또는 사용자가 직접 상황 입력 / 아젠다 선택)
        ▼
탐색 분석(AI 대화) 화면 ──질문──▶ 분석 API(/analyze)
        ▲                               │
        │                               ▼
        │                     LangGraph 에이전트
        │        ┌──────────────────────────────────────────┐
        │        │ ① 맥락 준비: 테이블 목록, 지표 사전, 아젠다 순서 │
        │        │ ② 분석가(LLM): 가설 세우고 도구 선택          │
        │        │ ③ 도구 실행 ⇄ ② 반복 (최대 12단계)            │
        │        │    - run_sql: GOLD·G1·도메인 읽기 전용 조회    │
        │        │    - python_analysis: 변화율·기여도 계산       │
        │        │ ④ 리포트 작성 (조회된 수치만 사용)            │
        │        │ ⑤ 서비스 DB에 리포트·SQL 기록 저장            │
        │        └──────────────────────────────────────────┘
        │                               │
        └──────리포트(요약·발견·원인·액션)──┘ → 분석 아카이브에 쌓임
```

## 2. 시스템 구성 (단계별)

### 지금 (v1, 개인 PC)
| 구성 | 기술 |
|---|---|
| 화면 | Streamlit (빠른 프로토타입) |
| 에이전트 | Python + LangGraph |
| LLM | OpenAI API (GPT) — 설정으로 Claude 등 교체 가능 |
| 분석 DB | 임시 SQLite (warehouse.db) |
| 서비스 DB | SQLite (service.db) |

### 팀 파일럿 (v2)
| 구성 | 기술 |
|---|---|
| 화면 | 기존 분석 허브 프론트엔드가 FastAPI 호출 (Streamlit은 내부 테스트용으로 유지) |
| API 서버 | FastAPI, Docker 컨테이너 1개 (사내 서버 또는 클라우드 VM) |
| 분석 DB | 회사 DW (GOLD·G1 스키마), **읽기 전용 계정** |
| 서비스 DB | PostgreSQL |
| 로그인 | 사내 SSO |

### 전사 운영 (v3)
| 구성 | 기술 |
|---|---|
| API | 컨테이너 여러 개 + 로드밸런서, 긴 분석은 작업 큐(Celery/Redis 등)로 비동기 처리 |
| Python 실행 | 별도 샌드박스 컨테이너 (보안 격리) |
| 권한 | 사용자/부서별 조회 가능 테이블 제한, 개인정보 컬럼 마스킹 |
| 운영 | 감사 로그(누가 어떤 SQL 실행), LLM 비용·사용량 모니터링, 답변 품질 평가 |
| 키 관리 | API 키는 Secret Manager에 보관 |

## 3. 데이터 흐름 원칙
- AI는 원천·SILVER를 직접 보지 않고 GOLD·G1·도메인만 읽습니다.
- 숫자 정의는 서비스 DB의 지표 사전을 따릅니다 (화면과 AI가 같은 정의 사용).
- 모든 리포트와 실행 SQL은 서비스 DB에 남겨 재현·검토가 가능합니다.
